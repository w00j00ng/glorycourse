# `Store.read()` 사용처 제거 계획

`Store.read()`는 현재 깊이 동결된 스냅샷을 복제 없이 반환한다. 따라서 호출명을 바꾸는 것만으로는 속도가 개선되지 않는다. 목표는 업무 코드에 전체 `DatabaseState`를 노출하지 않고, 필요한 자료와 버전만 저장 계층의 이름 있는 조회로 받는 것이다. 쓰기 직렬화와 확정된 스냅샷의 일관성은 유지한다.

2026-09-26 계획 시작 당시 운영 코드의 호출은 33곳이었다. 당시 분류는 버전 확인 6곳, API의 기준 자료·가져오기 배치 조회 2곳, 복합 업무 조회 24곳, 서버의 읽기 전용 핸들러 1곳이다. 사용자용 백업·복원 서비스는 이후 제거됐다. 테스트의 `store.read()`는 별도로 많으며 어댑터의 `read()`는 DB 재시작·실패 복구에 필요한 별도 계약이다.

1. **버전 조회:** `Store.version()`에서 epoch와 revision만 반환한다. 가져오기 검토, 이력 반영, 현황 다운로드의 버전 확인을 교체한다. 같은 응답 안에서는 두 값을 한 번에 읽고, 이전과 같은 충돌·재시도 결과를 테스트한다.
2. **단순 목록·단건 조회:** 학기·회원·강좌 목록과 가져오기 배치 단건 조회를 저장 계층의 명시적 조회로 옮긴다. 필요한 필드만 반환하고 정렬·페이지 결과와 없는 대상의 응답을 비교한다. 큰 원본 자료를 읽지 않는 경로부터 성능을 측정한다.
3. **복합 업무 조회:** 신청·이력·초안·확정·가져오기 미리보기의 참조 자료를 업무별 읽기 모델로 묶는다. `Store.query(callback)`처럼 전체 상태를 다시 노출하는 이름 바꾸기는 하지 않는다. 한 업무의 여러 자료는 같은 확정 스냅샷에서 읽고, 쓰기·내부 복원과 겹치는 요청의 revision 검사를 보존한다. SQL이 이득인 조회만 `backend/src/storage/queries/`의 전용 쿼리로 이동한다.
4. **공개 API 제거:** 서버의 읽기 전용 핸들러와 테스트를 새 조회 계약으로 옮긴 뒤 `Store.read()`를 삭제한다. `npm run verify`, `npm run test:browser`, `npm run test:storage-scale`, 복구·충돌 테스트를 통과시키고 운영 코드에서 `store.read()` 호출이 0곳인지 확인한다.

당시 버전 확인 6곳과 기준 자료 목록·가져오기 배치 단건 조회 2곳, 영수증·현황 확인 10곳, 신청·이력 조회 8곳, 초안 목록·상세 조회 2곳을 전용 조회로 옮겼다. 2026-10-03 현재 `version()`·`catalog()`·`getImportBatch()`·영수증 조회·`applicationData()`·`enrollmentData()`·`draftListData()`·`draftDetailData()`는 동결된 메모리 스냅샷에서 필요한 자료를 반환한다. 이를 SQL 조회로 전환했다고 해석하지 않는다.

## 남은 범위 (2026-10-03)

운영 코드의 `Store.read()` 호출은 5곳이다. 공개 API 제거 단계는 아직 완료되지 않았다.

| 파일 | 호출 수 | 남은 책임 |
| --- | ---: | --- |
| `backend/src/services/finalization.ts` | 2 | 확정 미리보기와 반영 전 현재 입력 검증 |
| `backend/src/services/import-preview.ts` | 2 | 새 파일 Preview와 STAGED 원본 재검토 |
| `backend/src/server.ts` | 1 | 읽기 전용 사용자 정의 API 핸들러의 저장소 노출 |

전용 읽기 모델로 이관할 때는 같은 스냅샷·epoch·revision 검사를 보존한다. `rg -n '\.read\(\)' backend/src`로 운영 호출을 확인하되 어댑터 읽기와 내부 실패 복구는 별도로 분류한다.

2026-10-04 추가된 `affiliation`도 조회 이관에서 보존해야 한다. 신청·초안 항목·이력과 초안의 입력 스냅샷은 각 기록에 저장된 소속을 반환하며, 회원 자료나 현재 신청의 소속으로 대체하지 않는다. 관련 계약은 [학생 소속의 시점별 보관](contract-decisions.md#c-14-학생-소속의-시점별-보관)을 따른다.
