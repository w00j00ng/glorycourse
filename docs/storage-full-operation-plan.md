# 저장소 전체 처리 점검과 대체 계획

일반 자료 수정은 메모리에서 변경 부분만 복사하고 SQLite에서도 변경된 행만 저장한다. 전체 상태를 읽는 `Store.read()` 호출은 별도 [제거 계획](store-read-removal-plan.md)에 따라 줄인다. 다음은 전체 DB·테이블 처리 경로를 실제 호출 기준으로 분류한 결과다.

| 경로 | 판단과 조치 |
| --- | --- |
| 일반 등록·수정·삭제 | 변경 행만 검증·저장한다. 전체 테이블 삭제나 DB 파일 복사는 없다. |
| DB 최초 생성 | 비어 있는 스키마에 초기 자료를 삽입한다. 기존 테이블을 지우는 SQL과 불필요한 초기 자료 복제를 제거한다. |
| 백업 복원 적용 | 기존에는 모든 업무 테이블을 삭제하고 다시 삽입했다. 현재 상태와 복원 후보의 차이만 한 트랜잭션에서 반영하도록 변경한다. 이전 상태 없이 채워진 DB를 덮어쓰려는 호출은 거부한다. |
| 스키마 마이그레이션 | 버전별 SQL이 필요한 기존 행을 변환한다. 확정 초안을 별도 영수증으로 옮긴 뒤 해당 초안 행만 삭제하는 일회성 이관은 유지한다. |
| 명시적 백업·복원 전 안전 사본·마이그레이션 전 안전 사본 | 특정 시점의 완전한 DB 사본이 목적이므로 전체 파일 복사를 유지한다. 복원 후보의 전체 검증과 복원 직전 백업도 유지한다. |
| 시작 시 DB 읽기·복원 후보 분리 | 메모리 상태의 초기 적재와 호출자 자료로부터의 분리는 자료 안전 경계라 유지한다. 백업을 읽은 직후의 중복 복제처럼 소유권을 이미 확보한 경우만 제거한다. |

검증 기준: 복원으로 회원 한 명만 달라질 때 다른 행에 삭제 방지 트리거를 걸어도 성공하고, 재시작 후 복원 내용이 일치해야 한다. 이전 상태가 없는 덮어쓰기 시도는 자료를 바꾸지 않아야 한다. 전체 `npm run verify`와 대량 저장 검증을 실행한다.
