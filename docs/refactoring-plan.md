# 저장 경로와 화면 분할 계획

## 목표와 완료 기준

- 한 건을 수정하는 `Store.write()`에서 전체 자료를 `structuredClone`하거나 전체 JSON Schema를 다시 검사하지 않는다. 변경 행과 메타데이터만 검증하고, 실패 시 메모리·SQLite가 모두 이전 상태를 유지한다.
- 기존 배치 반영·배정 확정·복원 동작과 쓰기 직렬화, revision 검사, 강제 종료 복구를 보존한다.
- 실제 혼합 자료에서 한 건 수정의 처리 시간과 SQLite 변경 행 수를 재측정한다. 수치 개선 없이 구조만 바뀐 경우 완료로 간주하지 않는다.
- `frontend/app.js`의 화면 책임을 분리된 파일로 옮기면서 사용자 흐름을 실제 브라우저에서 검증한다.

## 저장 경로

1. **회귀 기준:** 유효한 한 건 수정, 잘못된 행 거절, 쓰기 실패 후 재시도, 배치·복원, 변경 없는 큰 자료의 보존을 테스트한다. 기존 `tests/integration/store.test.mjs`, `tests/integration/sqlite-incremental.test.mjs`, `tests/operational/storage-scale.test.mjs`를 사용한다.
2. **변경된 경로만 복사:** `Store.write()`의 변경 콜백은 유지하고 copy-on-write 초안을 사용한다. 이전 상태는 성공한 SQLite 커밋까지 수정하지 않는다. `Store.read()`는 외부 코드가 내부 상태를 바꾸지 못하도록 복제하는 공개 조회 계약을 유지한다.
3. **변경 행만 검사:** `schema/store-schema.json`의 기존 행 정의를 재사용해 변경된 컬렉션의 새 행·수정 행과 `meta`만 검증한다. 전체 검증은 DB 열기·복원·마이그레이션에 유지한다. 외래키·고유값·순서는 기존 SQLite 제약과 트랜잭션에서 검증한다.
4. **저장 비교 축소:** 동일한 컬렉션은 SQL 변경 비교에서 건너뛰고, 변경된 컬렉션의 동일한 행은 다시 깊은 비교하지 않는다. 변경 행만 SQLite에 반영하는 기존 방식을 보존한다.
5. **검증:** `npm run verify`, `npm run test:crash`, `npm run test:storage-scale`, 실제 브라우저 핵심 흐름을 통과시킨다. 한 건 저장에 선행하는 전체 조회가 실제 병목으로 남으면 해당 업무에서 별도로 측정해 후속 범위를 정한다.

## `app.js` 분할

| 순서 | 책임 | 완료 확인 |
|---|---|---|
| 1 | 화면 공통 요청·페이지 이동의 경계를 확인하고 현재 외부 모듈 의존성을 기록한다 | 초기 화면·새로고침·늦은 응답 동작이 기존과 같음 |
| 2 | 수강신청 화면의 목록·수동 입력·양식 다운로드를 `frontend/applications-page.js`로 이동한다 | 등록·수정·검색·삭제 및 Excel 흐름의 사용자 테스트 통과, `checkJs` 포함 |
| 3 | 학기·강좌 관리 화면을 `frontend/catalog-page.js`로 이동한다 | 학기 이동·선택 해제·강좌 일괄 추가/복사/삭제의 사용자 테스트 통과 |
| 4 | 수강이력과 Excel 검토, 배정초안 편집을 각각 책임별 파일로 이동한다 | 기존 브라우저 흐름과 대량 초안 화면 검증 통과 |
| 5 | 남은 `app.js`를 초기화·화면 연결 역할로 축소한다 | `npm run typecheck`, `npm run verify`, `npm run test:browser`, 패키지 검증 통과 |

각 단계에서 실제로 옮기는 화면만 수정한다. 기존 `dashboard-page.js`, `backups-page.js`, `finalization-page.js` 패턴을 재사용하며 새로운 프레임워크나 전역 상태 관리 도구는 추가하지 않는다.

## 진행 현황 (2026-09-26)

- 저장 경로 1~5 완료. 혼합 자료 1만 명에서 한 회원 수정 3회의 중앙값은 19.0ms이며 SQLite 변경은 메타데이터 포함 2행이다. 전체 교체 저장 비교 경로는 836.8ms였다.
- 수강신청 화면의 목록 조회·표시, 수동 등록·수정·삭제, 양식 안내·다운로드를 `frontend/applications-page.js`로 옮겼다. 오래된 조회 응답, 여러 건 등록 후 현재 학기 재조회, 입력 행·삭제를 모듈 직접 테스트로 확인하고 `checkJs`에 포함했다. 실제 브라우저에서도 여러 건 등록 후 수정·삭제와 배정·이력 조회를 검증했다. 화면 이벤트 연결은 `app.js`에 남겨 두었다.
- 학기·강좌 화면의 학기 목록 표시·선택 해제·순서 이동, 상세 조회, 추가·이름 수정·삭제와 강좌 입력 행·일괄 추가·복사·저장·삭제를 `frontend/catalog-page.js`로 옮겨 `checkJs`에 포함했다. 학기와 복사 원본의 늦은 조회 응답을 직접 테스트하고, 실제 브라우저에서 강좌 추가·복사·저장·삭제를 확인했다. 공통 기준 자료 조회와 화면 이벤트 연결은 `app.js`에 남아 있다.
- 수강이력 목록 조회·표시, 현황 다운로드 완료, 입력 행·수정 팝업, 등록·수정과 개별·학기 전체 삭제를 `frontend/enrollments-page.js`로 옮겨 `checkJs`에 포함했다. 실제 브라우저에서 여러 건 등록, 기존 강좌 수정·저장, 개별 삭제 취소·확정, 학기 삭제 확인 문구와 결과, 배정 확정 후 이력 목록과 현황 다운로드·대시보드 완료 표시를 확인했다. 공통 기준 자료 조회와 화면 이벤트 연결은 `app.js`에 남아 있다.
- Excel 검토 화면의 열기·미리보기·충돌 선택·최종 반영을 `frontend/imports-page.js`로 옮겨 `checkJs`에 포함했다. 신청 양식의 후보 확인부터 반영까지 실제 브라우저에서, 반영 후 학기·신청·이력 재조회는 모듈 직접 테스트로 확인했다.
- 전체 검증 195개, 강제 종료 복구 3개, 실행기 5개, Chromium 사용자 흐름 11개를 통과했다. 새 화면 모듈을 포함한 Windows 패키지의 시작·저장·복원·종료 검증은 분할 초기 단계에서 수행했다.
